# Frontstage experience evidence matrix

Study date: 2026-10-01 UTC. Baselines: AVA Mother `a06acf9`, Critical Illness `af77e1c`, CIApp latest `main` at study time. The configured Critical Illness GAS read API returned `Plans`, `Benefits`, `Claim_Rules`, `Health_Program`, `Product_Content`, `Settings_Versions`, and four separate raw premium matrices.

| Experience / rule | Classification | Evidence and Frontstage treatment |
| --- | --- | --- |
| Support reserve and months | A — current app | `flow-state.js`: desired months × monthly need, protection ÷ positive monthly need. Selected plan total uses the same unit conversion; invalid need yields unavailable months. |
| SCE / OYS2 major CI | A — current Official data | `Plans` identifies each style; `Benefits` has `major_ci` at 100% for each. Customer enters the sum assured. Selecting both yields a labelled arithmetic total across selected items, with simultaneous payout qualification. |
| Early / child CI advances | D — verify required for aggregate | Official `Benefits` lists 20% advances. The exact subtraction and combined event conditions needed for a total are not established by these rows. Show descriptive source text, exclude from the summed amount. |
| First 10 year enhancement | D — verify required | Official `Benefits` has 50% / 35% entries, but age, event and first/last year eligibility boundaries are not fully established. `firstTenYearEnhancement()` stays gated. |
| Cancer first 100%, continuing shared 500% | A + B | Official `Claim_Rules` cancer rows are well formed; user confirms first 100% is outside the shared 500%, maximum structure 600%. Frontstage validates all expected fields before simulation. |
| Cancer A / B | A + B | Official rows: A 100% and 3-year interval; B 5% monthly and 1-year interval; shared pool ID; B lock. User confirms A→A/A→B/B→B, B→A forbidden. The existing claim engine consumes one pool. Timeline uses customer age in months. Contractual eligibility wording remains D. |
| Heart / stroke | A — current Official data | Live Official `OYS2_HEART_STROKE` now returns a well-formed rule: `payout_type=percent`, `payout_value=100`, `interval_value=1`, `interval_unit=year`, `max_claims=3`, with blank sequence. The strict Frontstage gate accepts these fields and the age timeline displays at most three applicable claims without a workaround. Contractual eligibility wording remains D. |
| Dementia | A + B | Live Official `OYS2_DEMENTIA_INITIAL` and `OYS2_DEMENTIA_ANNUITY` now return sequence 1 `percent=100%`, followed by sequence 2 `annual_percent=6%`, one-year interval, and `duration_rule=lifetime`. Frontstage uses the existing lifetime claim helper and age-based exploration; the selected age range is an exploration window, not a contractual cap. Contractual qualifiers and payment timing remain D. Legacy `maxCount=11` is rejected. |
| Premium matrix coordinate | A for header observation; D for production premium | Four separate Official sheets have age, gender-specific sheets, smoker and OYS2 10/18/25 header labels. Cells include zeros/blanks and hidden precision. `premium-engine.js` requires verified mappings and leaves rounding/monthly order unverified. Frontstage does not calculate a premium. |
| Premium formulas / projection | C — legacy reference only | CIApp `getRateFromTable`, `calculateCIPremium`, `renderProjectionTable`: fallback rates, `sum/7800 × rate`, `Math.round`, Vitality 0.9 for SCE, monthly `annual × 1.06 / 12`; 5-year projection blocks to age 80 and conditional waiver. No fallback, interpolation, assumed rounding, monthly result or total migrated. |
| OYS2 payment timeline | A for term labels; arithmetic only | Official premium matrix headers identify 10/18/25-year pay. Start age plus chosen term gives payment end age, labelled as a timeline only. SCE payment end and both premium totals remain D. |
| Vitality | A for descriptive record; D for premium amount | `Health_Program` describes SCE premium multiplier and OYS2 coverage bonus, but order, fee application and premium/benefit interaction are not fully verified. Input is retained; no money effect is calculated. |

Legacy interaction traced: `runStage3Calculation()` adds selected SCE/OYS2 claim figures; `executeDynamicClaim()` and `renderMultiButtonsFromRules()` build the old mixed claim timeline; `calculateCIPremium()` and `renderProjectionTable()` drive the old premium cards/table. Their hardcoded defaults and UI are not migrated. The rebuilt pages use current Official datasets, current User Override storage and current plan routing.
